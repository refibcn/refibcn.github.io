Buttons & links

The .btn and .link primitive classes (src/styles/global.css §6.1/§6.4) plus the Button.astro wrapper component.

component unused on real pages

Button

Button.astro wraps .btn (renders an <a> if given href, else a <button>). It's a clean component — but every real page currently hand-writes <a class="btn btn--primary"> directly instead of importing it (see Hero, CTABand, Nav). Worth either switching those over to the component, or, if the raw-markup pattern is intentional, dropping the unused wrapper.

Variants

Primary runs on --btn-primary-bg (→ --umber), not --primary (the red pillar-flow accent) — a deliberate split from the brand color for the everyday button action. Disabled state is in States below.

Sizes

size="sm" | "md" | "lg" (default md). See Typography for the full size spec.

Icons

Named icon-left / icon-right slots — pass anything (plain characters here; any inline SVG works the same way). .btn__label handles the gap between icon and text.

States

live

Default, Hover, Active, Disabled for each variant. Hover/Active are forced static here with page-local .demo-hover/.demo-active classes so they can sit side by side — they mirror the real :hover/:active rules in global.css exactly (they read the same --btn-primary-* tokens, which is also what makes the "on dark" row below work). Hovering or clicking the real buttons above does the same thing live.

On dark

speculative — nothing on the live site uses this yet

Wrap any block in .on-dark (src/styles/themes/editorial-organic.css) to flip it for a dark section. Nothing on refibcn.github.io needs this today, but this design system is meant to serve more than one light editorial website — client work, other products — so the inversion exists as a real, working context now rather than getting invented ad hoc later. Every semantic token flips (--bg, --surface-*, --text-*, --border-*, --btn-primary-*), so buttons, cards, and text all adapt with zero component changes.
